# Reproducing experiments

Use Linux or WSL with the environment in `environment.yml`. Run commands from
the repository root. Put all companion Release ZIPs in one directory and set
`DUAL_COPPERSMITH_DATA` to that directory. Each ZIP and every extracted member
is SHA-256 checked. About 3 GiB of space is needed for unpacked reference data,
in addition to the compressed assets; new searches can use substantially more.

## Quick validation and summaries

```bash
python scripts/verify_submission.py
python -m unittest discover -s tests -v
python scripts/make_tables.py --output /tmp/dual-tables
python scripts/plot_results.py --output /tmp/dual-figures
python scripts/smoke.py --work /tmp/dual-smoke
```

The smoke suite tests modular kernels, small exhaustive minima, resumable
search, coefficient exclusion, rejection of corrupted Gram decompositions,
and one small HM recovery instance. It does not run the paper grids.

## Validate archived bounds

```bash
python scripts/verify_submission.py --data-dir "$DUAL_COPPERSMITH_DATA"
python scripts/verify_science.py --work /tmp/dual-science
```

The default verifies all 21 original-lattice interval witnesses and exact
algebra, including all tested certificates for the five optimized bases.
Use `--indices 1,2,3,8,9` to check only those cases. To rerun the decisive
small SVPs, choose a time limit per block:

```bash
python scripts/verify_science.py --work /tmp/dual-science-replay --replay-seconds 240
```

Timeout is a failed replay, not new proof credit. These checks use archived
completion records for other blocks and full-dimensional searches. Full
shortestness certification requires complete frontier coverage under the
trusted enumeration implementation, as described in `METHODS.md`.

## Seeded geometry and a fresh projected search

Case identifiers are listed in `configs/cases_21.json`. The smallest HM case
provides a quick fresh search:

```bash
python scripts/run_experiment.py geometry --case hm-t3-m3-ell2-seed0 \
  --work /tmp/dual-fresh-geometry --fresh-geometry
python scripts/run_experiment.py projected --case hm-t3-m3-ell2-seed0 \
  --work /tmp/dual-fresh-search --new-search -- --kind jet --backend native --seconds 120
```

Without `--new-search`, an archived exact minimum can be reused; the program
prints `MINIMUM_REUSED`. With it, cached minima and search checkpoints for the
selected objective are omitted. Fresh geometry alone uses no cached geometry.

## Original minima, RHF, and basis optimization

```bash
python scripts/run_experiment.py original-minima --case acd-t2-m1-ell10-seed0 \
  --work /tmp/dual-original --new-search -- --seconds 120 --workers 1
python scripts/run_experiment.py rhf --work /tmp/dual-rhf
python scripts/run_experiment.py optimize --case acd-t2-m1-ell11-seed0 \
  --work /tmp/dual-optimize -- --quick
python scripts/run_experiment.py certify-bounds --case acd-t2-m1-ell11-seed0 \
  --work /tmp/dual-optimize --no-unpack -- --help
```

Use `-- --help` for an engine's full options. Each experiment should have its
own work directory so regenerated outputs do not overwrite the archived
reference data. Historical elapsed times are retained as measurements from
their original runs, not expected timings on another machine.
When continuing in an initialized work directory whose generated reports have
changed, pass `--no-unpack`. Otherwise reference extraction refuses to overwrite
a file whose contents differ from the archived copy.

Some large deterministic `integer.prepared` files are omitted to avoid
duplicating their exact source Grams. Before replaying an archived stage
that requires one, rebuild it and require its archived checksum to match:

```bash
python scripts/rebuild_preparation.py /path/to/work/certificates/CASE/STAGE/pass1
```

Preparation may be expensive at high dimension. Completed frontier snapshots
are supplied separately from partial exploratory queues. Omitted incomplete
queues can be regenerated by a new search; the archive is not a snapshot of
every job still running in the original workspace.

## Optional sieving

The candidate search uses the pinned G6K kernel in `third_party/manifest.json`.
Install `git`, `autoconf`, `automake`, `libtool`, `pkg-config`, and GNU compilers,
then build in an experiment workspace:

```bash
bash scripts/build_g6k.sh /tmp/dual-sieve
python scripts/run_experiment.py sieve --work /tmp/dual-sieve -- \
  /path/to/projected/certificate/pass1 --algorithm bgj1 --context 80 --seconds 180
```

Hydrate the desired case and rebuild its preparation first. G6K generates
heuristic candidate upper bounds; a successful sieve is not a shortestness
certificate. The optional upstream download and container build are distinct
from the local scientific validation reported in `VALIDATION.json`.

## Container recipe

`Dockerfile` provides a Linux environment recipe. Building it requires network
access to install the conda packages. Check `VALIDATION.json` for whether the
container was built in this release; a supplied recipe alone is not a claim
that its build has been tested.
